一、项目说明
**需求：电商下单 + 优惠券**
基础规则：
- 商品可加入购物车，数量 1–99
- 优惠券类型：满 100 减 20、满 200 减 50、新人券（无门槛减 10）
- 满减券**不能叠加**，新人券**可与满减券叠加一次**
- 优惠后金额不能低于 0
- 支持微信 / 支付宝 / 余额三种支付
- 余额不足时支付失败
要求产出**不少于 35 条**用例：
1. 先写一份**需求澄清清单**（至少 8 问），比如：券有有效期吗？退款后券退不退？
   券有有效期吗？有效期多久？过期了是自动失效还是能手动退？退款的商品如果用了券，券退不退？退的是券还是钱？
2. **判定表**：优惠券叠加规则
3. **场景法**：下单主流程 + 至少 6 条备选流
4. **等价类 + 边界值**：数量、金额
5. **跳转用例**：从商品页 → 购物车 → 结算页 → 支付页，每一步的跳转本身要测（带参、返回后状态）
6. 每条用例标 **P0–P3**

二、运行方式
_build_cases.py 是一个纯生成脚本：它没有命令行参数，运行时会把 Excel 输出到当前目录，输出的文件名写死为 练习册E_电商下单+优惠券_测试用例.xlsx，如果该文件已经存在，会直接覆盖。
依赖 openpyxl，不需要其他库。
几点说明：
必须进入脚本所在目录后再运行。因为脚本最后一行使用的是相对路径，如果在别的目录执行，文件就会写到那个目录去。
成功时终端会打印 saved: ... cases: 69。注意 Windows 终端里中文会显示成乱码，那是 console 编码问题，文件本身没有问题。
所有用例数据都在文件顶部的 CASES 列表里，格式是 (编号, 模块, 标题, 优先级, 前置条件, 步骤, 测试数据, 预期结果)。要增加用例，就往这个列表里追加元组；要修改文案，就直接改对应字符串，然后重新运行。
统计页的 COUNTIF 范围由 len(CASES) 自动算出（LAST 变量），所以增加用例后不用手动调整公式。

三、用例覆盖
覆盖9个模块，包括订单流程、购物车-加购、购物车-数量、兼容性与界面、金额计算、网络与环境、页面跳转、优惠券以及支付，总计测试用例69 条。
